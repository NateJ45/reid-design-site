# Stack and Astro config

> Full stack/version notes and the astro.config.mjs levers that look tempting but break things.

## Stack

Pinned versions reflect what's known to work together as of May 2026. Bump deliberately, not casually.

- Astro **7.3.1** (7.2.9 at the 2026-08-28 upgrade; patch-bumped by the 2026-09-06 dependabot group) with TypeScript in strict mode and `output: 'static'` plus a few `prerender = false` SSR routes. Requires Node 22.12+. Upgraded 2026-08-28 from 6.3.8. **The old 6.3.8 pin is retired, and so is its reason**: the 2026-06-11 revert existed because `@astrojs/cloudflare` 13.7.0 under `imageService: 'compile'` stopped emitting the original for local images used only via `getImage()` (the theme-swap header/footer logos, which never render their original PNG), so the build-time optimizer hit `ENOENT` on `dist/_astro/logo-*.png` and every Cloudflare build failed. Adapter 14.2.4 does not have that bug: all ten logo variants optimize cleanly on every build here. Keep the story, drop the pin.
- **`@astrojs/cloudflare` pinned EXACTLY at 14.3.0**, and **`wrangler` at `~4.129.0`** (verified against `package-lock.json` 2026-09-29). History: 14.2.4 with `~4.110.0` at the 2026-08-28 upgrade; wrangler moved to 4.129.0 on 2026-09-05 (a bundled sharp/undici advisory); the adapter to 14.3.0 in the 2026-09-06 dependabot group (#32). The peer rule that made them a pair still holds: 14.2.5+ peers `wrangler ^4.125.0`, and wrangler 4.126+ rejects the `legacy_env` field the adapter writes into `dist/server/wrangler.json` on some configs. The current pair is safe because on THIS config the generated file carries no `legacy_env` at all (checked on a 14.3.0 build, 2026-09-29). Moving either is still a deliberate act: bump both, rebuild, read the generated config, and run a real `wrangler dev` before believing it.
- **Vite 8**, and there is deliberately **no `vite` override**. The repo used to carry `"overrides": { "vite": "^7" }`. Astro 7.x depends on `vite ^8.0.13` and its static build calls `vite.createBuilder()`; held at 7.3.3 the build got all the way through the client bundle and then died on `Could not find the prerender entry point in the build output. This is likely a bug in Astro.` It is not a bug in Astro, it is a silently downgraded vite. If a transitive package ever seems to want a vite pin again, check Astro's peer range first.
- **Sanity 6.9.1** as the headless CMS, in THIS package, with the Studio embedded at `/studio` via `@sanity/astro` (2026-08-28; the nested `studio/` package is gone, and so is the separately deployed `reid-design.sanity.studio`). Schemas in `src/sanity/schemaTypes/`, written with `defineType`/`defineField`/`defineArrayMember` from `'sanity'`. TypeGen runs from the repo root (`npm run typegen` = `sanity schema extract --force && sanity typegen generate`). The Sanity dependency set is a matched SET, not a list of independent pins; the whole story, including the one-module-instance invariant and how to verify it, is in `docs/agent/sanity.md`.
- Tailwind 4 via `@tailwindcss/vite`. Brand tokens declared in `@theme` blocks inside `src/styles/globals.css`. There is no `tailwind.config.mjs` file.
- React 19 islands for anything interactive (mobile nav drawer, contact form, lightbox, back-to-top, before/after slider for case studies, filter chips). Astro components for everything static.
- shadcn/ui primitives in `src/components/ui/` (Nova preset, Radix base). Extend Button with project-specific marketing variants only when the standard variants don't carry the brand.
- Motion (formerly Framer Motion), Astro View Transitions, Lenis smooth scroll (respecting `prefers-reduced-motion`).
- react-photo-album for justified gallery layouts in case studies.
- yet-another-react-lightbox for fullscreen project gallery viewing (with Zoom and Thumbnails plugins).
- sharp for image processing. Sanity handles its own image transformation pipeline for content images; sharp is for any locally-bundled assets (logo, OG image generator).
- The share cards are drawn at build time by `src/integrations/og-cards.ts` through `scripts/lib/og-render.mjs`: sharp prepares every image, satori + @resvg/resvg-js set the text (no browser) in the site's own Zodiak Light and General Sans Medium, as .woff copies in `scripts/.og-fonts/` (design F "the cover" since 2026-09-30). opentype.js is no longer used.
- `@astrojs/rss` is still a dependency but nothing uses it: the only feed, `/journal/rss.xml`, was removed 2026-09-30 with the journal (never launched).
- `@astrojs/sitemap` for `sitemap-index.xml` (production sitemap).
- **Light only (since 2026-09-29).** BaseLayout's theme bootstrap never adds `.dark`; `ThemeToggle` was removed from the header and mobile drawer; the `.dark` tokens in `globals.css` are dormant (the footer applies `.dark` to its own subtree for the ink footer). The `localStorage["reid-design-theme"]` key is ignored. How dark could return: docs/agent/theme-and-color.md.
- **Fonts (since 2026-09-29):** Zodiak (display) + General Sans (text) from Fontshare, ITF Free Font License 2.0. The woff2 files are NOT committed: `scripts/fetch-fonts.mjs` downloads them into gitignored `public/fonts/` on `predev` and `prebuild`, verifying SHA-256 against `scripts/fonts.lock.json` (`npm run fonts:update` rewrites the lock). See docs/agent/design-tokens.md. The `@fontsource` packages for the old faces are still installed pending removal.
- `src/data/site.ts` as the single source of truth for hardcoded site identity (brand name, domain, asset paths, social URL strings the build needs at compile time). Anything Staci edits goes through Sanity instead, including the publicly displayed contact info.
- **Web3Forms** for the contact form (matches NCS pattern). Free tier covers 250 submissions/month, more than Reid Design needs.
- **Calendly** embed (or link) for the 20-minute discovery call.
- Cloudflare Web Analytics for privacy-friendly traffic (no cookie banner needed).
- **Cloudflare Workers** for hosting (not Pages). The two products merged in early 2026; Pages is in maintenance mode, Workers gets all new investment. Use `wrangler deploy`. Astro adapter config is `cloudflare({ imageService: 'compile' })` so image processing stays at build-time via Sharp — never reaches the Cloudflare Images runtime binding (avoids surprise per-transform fees, no Workers binding required).
- GitHub for version control.

### Astro config don'ts

A few `astro.config.mjs` levers that look tempting but break things — left documented here so a future agent doesn't waste a cycle rediscovering them:

- **`security.csp` is disabled on purpose.** Astro 6 has a hash-based CSP feature that auto-generates SHA-256 hashes for inline scripts + styles. Enabling it satisfies Lighthouse's `csp-xss` audit on paper, but in practice the build-time hash pass misses at least one runtime-generated inline script (ClientRouter's view-transitions runtime emits one) and one inline style from the astro-island markup. The browser then blocks them — theme bootstrap breaks, Lenis init breaks, polish observer breaks. Re-enabling would need either nonce-based SSR (doesn't apply to our `output: 'static'`) or an audit of every inline script Astro and React might emit at runtime. Not worth chasing for an unscored audit. Since 2026-09-29 the real policy lives in `public/_headers` instead: a full header-delivered CSP with `'unsafe-inline'` on scripts and styles, scoped separately for the public site and the embedded Studio (see deployment.md, "Security headers").
- **Do not remove `fixSanityDedupeAlias()` (the PORTABLE `src/lib/sanity-dedupe-alias.ts`, PORTS.md card 60) from `vite.plugins`, and do not "fix" dev by setting `SANITY_ASTRO_DISABLE_MODULE_DEDUPE`** (2026-09-29). Without the plugin, `npm run dev` on Windows exits within a minute: `Error during dependency optimization: Build failed with 364 errors: [MISSING_EXPORT] "DocumentStatus" is not exported by "node_modules/sanity/package.json"`. @sanity/astro's dev-only `sanity:module-dedupe` plugin (3.4.2, still present in 3.5.1) aliases `sanity` and `styled-components` to their package folders, but strips `/package.json` off the resolved path with a forward-slash-only regex, so on Windows the alias points at the `package.json` FILE. `npm run build` never loads that plugin, which is why CI and production were unaffected. The canonical plugin is a `post` config hook that strips the stray `\package.json` from those alias entries and is a no-op on macOS/Linux or once upstream fixes it. Switching the upstream plugin off with its env var was tried first and is worse: the server stays up but the Studio will not hydrate (`react-compiler-runtime ... does not provide an export named 'c'`), because the same plugin also pre-bundles the CJS packages the Studio needs in dev. Delete it (and its vitest spec, `src/lib/sanity-dedupe-alias.test.ts`, which is Reid-local because the starter runs node:test) once `sanity:module-dedupe` in `node_modules/@sanity/astro/dist` uses a separator-safe replace. Side note for agents: Astro 7 runs `astro dev` in the background when it detects an AI agent, logs to `.astro/dev.log`, and gives up after 30 s, which a cold optimizer cache can exceed; run `ASTRO_DEV_BACKGROUND=1 node node_modules/astro/bin/astro.mjs dev` to get a normal foreground server.
- **`crossorigin="anonymous"` on Sanity CDN images breaks them.** Sanity's CDN doesn't send `Access-Control-Allow-Origin` for credential-less image requests, so the browser refuses the response and the image fails to render. Lighthouse's third-party-cookie warning about `sanitySession` is a real cookie but the only known fix would proxy every image through a Cloudflare Worker — not worth the engineering for an unscored Best Practices flag.
